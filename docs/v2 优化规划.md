# CoreCoder-Web v2 规划：从单会话页面到对话工作台

> 更新日期：2026-08-08
> 本文以当前代码为基线，重新定义 v2 的产品形态和实施顺序。已经完成的工作保留为技术基线，不再混入待办列表。

> 实施状态：M1–M3 已于 2026-08-08 完成；M4–M5 保留为后续工作。

## 1. 方向调整

CoreCoder-Web 的核心任务是让用户在一个工作空间内持续和 Agent 协作，而不是在浏览器里复刻一套轻量 IDE。

v2 调整为对话优先的双栏工作台：

```text
┌──────────────────┬────────────────────────────────────┐
│ 当前工作空间       │ 当前对话                            │
│ ＋ 新建对话         │                                    │
│                  │ 消息                                 │
│ 对话历史           │ 工具调用卡片（随消息流展示）           │
│                  │                                    │
│                  │ 输入框                               │
└──────────────────┴────────────────────────────────────┘
```

- 左侧边栏展示当前工作空间下的对话历史，不再常驻文件树。
- 右侧保留完整聊天流，工具调用继续穿插在对应消息中展示。
- 文件修改仍通过确认卡片进入 diff；完整 diff 点击后在弹窗中查看，不占用固定页面区域。
- 文件树和文件预览不再是主界面功能。后续如需引用文件，使用搜索、选择器或 `@文件` 入口，复用现有文件接口。

此前完成的文件树虚拟滚动属于有效的技术优化，但它服务于旧布局。v2 不会因为已经投入开发成本而继续保留常驻文件树。

## 2. v2 范围

v2 要解决的是“同一工作空间中的多轮、多会话协作”：

- 新建对话；
- 查看当前工作空间的对话历史；
- 在多个对话之间切换，消息和工具记录互不混淆；
- 刷新或重启服务后恢复历史对话；
- 清楚展示对话的运行、等待确认、失败和完成状态；
- 在当前对话内完成工具确认和 diff 查看。

本阶段不做：

- 多用户权限系统；
- 同一服务同时挂载多个工作空间；
- 浏览器内完整文件管理器或 IDE；
- 多个对话同时后台执行；
- 独立的 diff 页面；
- 左侧文件树搜索和固定文件预览面板。

第一版明确限制为“一个工作空间、多个对话、同一时间一个对话运行”。这与当前进程级事件和确认机制相符，也能避免为了历史列表提前引入多用户调度系统。

## 3. 当前基线

截至 2026-08-08，项目已经具备以下能力：

- 聊天消息通过 SSE 流式返回；
- 工具开始、结束和结果可以在聊天流中展示；
- `edit_file`、`write_file` 和危险 `bash` 共用确认流程；
- 多个待确认工具调用按顺序弹出，不会互相覆盖；
- 页面刷新后可以恢复当前进程内的消息和待确认状态；
- Monaco Diff 按需加载，首页不再预加载编辑器；
- 文件树采用懒加载和虚拟滚动；
- 前端类型检查、构建和 Python 发布流程已接入 CI。

当前实现仍然只有一个全局 `Agent`。会话消息、SSE 事件和确认状态都围绕这个实例工作；磁盘 session 也没有工作空间归属。这是 v2 首先要拆开的边界。

## 4. 核心模型

### 4.1 WebSession

Web 端不直接把 `Agent.messages` 当作会话模型。新增稳定的 `WebSession`：

```text
WebSession
  id
  workspace_id
  title
  model
  created_at
  updated_at
  status: idle | running | waiting_confirmation | interrupted | error
  messages
```

其中：

- `workspace_id` 由规范化后的工作空间路径生成稳定摘要，列表接口只返回当前工作空间的数据；
- `title` 第一版取首条用户消息的单行摘要，允许用户手动修改；
- `status` 是服务端状态，不由前端根据最后一条消息猜测；
- `messages` 落盘保存 provider 所需的完整上下文，接口输出时转换为稳定的 UI DTO。

每个会话拥有独立 `Agent`，不要在一个全局 `Agent` 上反复替换 `messages`。后者在请求切换、异常恢复和未来并发场景中很容易串话。

### 4.2 WebSessionManager

新增 `WebSessionManager`，统一负责：

- 创建、读取、重命名和归档会话；
- 按当前工作空间列出会话；
- 管理会话对应的 `Agent` 实例；
- 保存消息和状态；
- 保证同一时间最多一个会话运行；
- 服务重启后把未完成的 `running` 或 `waiting_confirmation` 会话标记为 `interrupted`。

第一版不实现多个 Agent 并行运行。某个会话正在执行时，其他会话仍可查看；向其他会话发送消息返回 `409 Conflict`，前端给出明确提示。

### 4.3 存储

现有 `~/.corecoder/sessions` 主要面向 CLI，缺少工作空间信息，不适合直接作为 Web 对话列表。

v2 使用独立目录：

```text
~/.corecoder/web-sessions/<workspace_id>/<session_id>.json
```

存储约束：

- 先写临时文件，再原子替换正式文件；
- 每轮回复结束、确认结果产生和标题修改后保存；
- 单个损坏文件不能阻断整个会话列表；
- 列表接口只读取摘要，不为展示列表加载所有消息；
- 待确认 payload 可能含完整文件内容，不作为可继续执行的任务落盘；
- session 文件可能包含代码、命令和工具输出，日志不得再次打印完整内容。

CLI session 与 Web session 暂不自动混合。后续若确有需要，再提供显式导入，而不是把无法判断工作空间归属的旧记录直接展示出来。

## 5. 接口调整

所有影响会话状态的接口都显式携带 `session_id`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/sessions` | 列出当前工作空间的会话摘要 |
| `POST` | `/api/sessions` | 新建空会话 |
| `GET` | `/api/sessions/{session_id}` | 获取会话消息和状态 |
| `PATCH` | `/api/sessions/{session_id}` | 修改标题或归档状态 |
| `DELETE` | `/api/sessions/{session_id}` | 删除会话，前端必须二次确认 |
| `POST` | `/api/sessions/{session_id}/chat` | 在指定会话中发起 SSE 对话 |
| `GET` | `/api/sessions/{session_id}/pending` | 查询该会话的待确认操作 |
| `POST` | `/api/sessions/{session_id}/confirm` | 提交批准或拒绝结果 |

迁移期间保留现有 `/api/chat`、`/api/session/messages` 和 `/api/session/pending`，内部转发到默认会话。前端完成切换后再移除兼容层，避免后端和界面必须在一个提交中同时翻转。

列表摘要至少包含：

```json
{
  "id": "session-id",
  "title": "修复登录回调",
  "preview": "请检查 OAuth 回调失败的问题",
  "status": "idle",
  "created_at": "2026-08-08T10:00:00+08:00",
  "updated_at": "2026-08-08T10:15:00+08:00"
}
```

## 6. 前端结构

### 6.1 左侧会话栏

新增 `SessionSidebar`，替换 `App.vue` 中的常驻 `FileTree`。

会话栏从上到下包括：

- 当前工作空间名称；
- 新建对话按钮；
- 按 `updated_at` 倒序排列的会话列表；
- 会话标题、简短预览、更新时间和运行状态；
- 重命名、归档或删除入口。

选中项由路由或本地持久化状态保存。刷新后优先回到上次打开的有效会话；如果会话已删除，则打开最近更新的一条；当前工作空间没有历史时，展示新对话空状态。

窄屏下左栏改为抽屉，不压缩聊天正文。

### 6.2 聊天区

聊天区继续使用现有的消息流结构：

- 用户消息和 Agent 回复按时间排列；
- 工具开始、参数、结果和失败状态仍显示在调用发生的位置；
- 切换会话时，从服务端重新加载该会话 DTO；
- 正在运行的会话在侧边栏和标题栏同时显示状态；
- 切换到其他会话不会把当前流式内容追加到新会话。

前端状态必须按 `session_id` 路由事件。即使第一版只允许一个运行任务，也不能再把所有 SSE 消息默认写入“当前选中的聊天”。

### 6.3 diff 与文件入口

diff 行为保持不变：

- 确认卡片展示操作摘要；
- 点击“查看 diff”打开 Monaco Diff 弹窗；
- 批准或拒绝后回到原聊天位置；
- 关闭弹窗不等于拒绝操作。

`/api/tree` 和 `/api/file` 暂时保留，但不再驱动固定文件树。未来的文件引用选择器、路径补全和 diff 上下文可以继续复用这些接口。

## 7. 实施阶段

### M1：会话基础（P0，已完成）

工作项：

- 定义 `WebSession` schema 和 UI DTO；
- 实现工作空间 ID、磁盘目录和原子保存；
- 实现 `WebSessionManager`；
- 增加列表、新建、详情接口；
- 为损坏文件、工作空间隔离和重启恢复补单元测试。

验收标准：

- 同一工作空间重启服务后仍能看到历史；
- 另一个工作空间不会看到这些记录；
- 单个 session 文件损坏时，其余会话仍可打开；
- 重启前未完成的会话显示为 `interrupted`，不会自动继续执行。

### M2：对话工作台（P0，已完成）

工作项：

- 用 `SessionSidebar` 替换主布局中的 `FileTree`；
- 支持新建、选择、重命名和删除会话；
- 切换会话时恢复消息与工具记录；
- 保存并恢复最近打开的会话；
- 完成桌面与窄屏布局。

验收标准：

- 可以连续创建并切换至少 20 个会话；
- 每个会话只显示自己的消息和工具记录；
- 刷新页面后仍停留在上次会话；
- 主界面不再常驻文件树；
- 工具卡片位置和 diff 弹窗行为与当前版本一致。

### M3：运行状态与确认隔离（P0，已完成）

工作项：

- 将聊天、pending 和 confirm 接口迁移到 session 路径；
- SSE 事件携带并校验 `session_id`；
- 确认状态按会话查询，不依赖前端当前选中项；
- 增加单运行任务锁和 `409` 错误处理；
- 页面刷新后恢复对应会话的待确认弹窗和最终回复轮询。

验收标准：

- 会话 A 运行时切到会话 B，A 的事件不会写入 B；
- A 等待确认时刷新页面，确认框仍归属于 A；
- B 在 A 运行期间发起请求时得到可理解的占用提示；
- 批准、拒绝和连接中断后，会话状态都能回到稳定值。

多会话并行执行不属于这一阶段。若以后开放并行，需要把事件总线、确认 registry 和运行资源改为每会话实例，再单独评估资源限制。

### M4：可靠性与安全（P1）

工作项：

- 引入 Playwright，覆盖创建、切换、刷新、确认和 diff；
- 增加前端错误边界和 SSE 断线提示；
- 为 session 写入失败、LLM 异常和工具异常补恢复路径；
- 完善 Bash 在 PowerShell、CMD 和 POSIX shell 下的高风险命令测试；
- 若引入 Markdown 渲染，同时接入 HTML 清洗并保留纯文本回退。

验收标准：

- 核心对话流程在 CI 中端到端运行；
- 网络中断或组件异常不会导致整页白屏；
- 失败状态不会永久锁住新请求；
- Markdown 内容不能执行脚本、内联事件或危险链接。

### M5：按反馈扩展（P2）

完成主流程并观察真实使用后，再决定是否加入：

- 对话搜索、归档和批量清理；
- 自动生成更准确的会话标题；
- `@文件`、文件搜索或最近文件选择器；
- 上下文压缩提示和 token 使用概览；
- 多会话后台运行；
- 多工作空间和多用户隔离。

这些项目不能反向影响 M1–M3 的交付边界。

## 9. 风险与约束

### 会话串扰

最大的功能风险不是列表展示，而是 SSE 事件、确认结果和 `Agent.messages` 写入错误会话。所有异步回调必须携带创建时的 `session_id`，不能在回调发生时读取“当前选中会话”。

### 敏感信息落盘

对话历史可能包含源码、命令输出、密钥片段和文件 diff。需要明确 session 目录权限、错误日志脱敏和删除行为。前端删除必须二次确认；后端只允许操作当前工作空间分区内的合法 session ID。

### 历史体积

长对话和大型工具输出会使 session 文件快速增长。M1 至少要设置单条工具结果和列表 preview 的长度上限，并记录文件体积指标。上下文压缩与历史归档可以后续做，不能在没有提示的情况下静默丢弃用户可见消息。

### 切换中的运行任务

允许查看其他会话，但第一版不允许同时运行。这个限制要通过状态和提示表达清楚，不能表现成输入框无响应。

## 10. 完成定义

v2 主流程完成时，应同时满足：

- 左侧只展示当前工作空间的对话历史，右侧是聊天区；
- 新建、切换、重命名和删除会话可用；
- 刷新浏览器和重启服务后历史仍可恢复；
- 消息、工具事件和确认结果不会跨会话；
- 工具调用仍在聊天过程中展示；
- diff 仍通过点击打开弹窗，不常驻占用布局；
- 主页面不再显示文件树，现有文件接口没有被仓促删除；
- 后端单元测试、前端类型检查与构建、核心 E2E 全部通过；
- README、接口说明和规划文档与最终行为一致。

## 11. 建议执行顺序

```text
1. WebSession schema、存储和 WebSessionManager
2. 会话 API 与后端测试
3. SessionSidebar 和会话切换
4. chat / pending / confirm 按 session_id 迁移
5. 运行锁、刷新恢复和异常状态修复
6. 从主布局移除 FileTree，清理无引用前端代码
7. E2E、错误边界和安全测试
8. 根据真实反馈选择文件引用、搜索或并发能力
```

这个顺序先建立可靠的会话边界，再替换界面。文件树移除安排在新侧边栏可用之后，以保证每一步都能独立验证和回退。
