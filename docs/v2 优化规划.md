# CoreCoder-Web v2 优化规划

> MVP 主要功能于 2026-08-06 落地，2026-08-08 完成关键集成修复。本文档以当前代码为基线；已完成项目保留记录但不再进入待办顺序。

---

## 概述

五层优先级：

- **P0** — 用户直接感知的体验痛点，优先修
- **P1** — 不改会限制后续功能的架构债
- **P2** — 安全加固
- **P3** — 功能扩展
- **P4** — 工程质量

---

## P0 — 体验修复（已完成，2026-08-08）

### 1. 刷新保留对话消息（已完成）

新增 `GET /api/session/messages`，后端把 provider 格式历史归并成稳定的 UI DTO：用户消息、助手文本、工具参数、结果及明确的 `running`/`done` 状态。前端启动时恢复 DTO，不直接依赖内部 `agent.messages` 格式。

刷新发生在确认期间时，批准/拒绝后前端根据后端 `running` 状态轮询，直到恢复最终回复。仍只恢复当前进程内的会话，不做磁盘持久化。

---

### 2. Monaco 体积瘦身（已完成）

`DiffViewer` 改为动态导入 `editor.api`，只注册 Python、JavaScript、TypeScript、Shell 和 JSON，并根据文件扩展名选择语言。组件卸载时主动销毁 editor 和两个 model。

生产构建实测：最大 JS 从 3.29 MB（gzip 846 KB）降至 2.29 MB（gzip 595 KB），约减少 30%；首页 HTML 不包含 Monaco 的 `modulepreload`，只有打开 diff 时才加载。曾验证 `manualChunks`，但它会让 Vite 在首页预加载 Monaco，因此最终没有采用。

---

### 3. 文件树虚拟滚动（已完成）

文件树保留目录懒加载，但渲染从递归组件改为“展开树扁平化 + 固定行高虚拟窗口”。无论展开多少节点，DOM 只保留视口行和上下各 8 行缓冲；400px 视口通常约 31 行，不再随累计展开节点线性增长。

没有引入额外依赖。`ResizeObserver` 跟踪视口高度，滚动位置计算可见切片和上下 spacer；目录数据仍按展开请求。后续只有在单目录响应本身成为瓶颈时，才需要给 `/api/tree` 增加分页。

## P1 — 架构债

### 4. 并行工具调用确认阻塞（已完成，2026-08-08）

`agent.py` 已使用 `as_completed()`，普通工具完成后立即发出 `tool_end`。确认型工具统一经过 `_confirmable.py` 的 `_confirmation_gate`，按顺序弹窗，解决多个 `confirm_required` 覆盖单个前端 modal 的问题。对应并发回归测试位于 `tests/test_web.py`。

---

### 5. 多 Workspace / 多用户隔离

**现状**：以下对象是进程级单例，在"单用户单 workspace"假设下安全：

- `ConfirmRegistry`（`confirm_registry.py` 的 `registry`）
- `events._sse_emit`（事件总线）
- `BashTool` 的 `cwd` 读取方式

**方案**：

- `ConfirmRegistry` → `dict[workspace_id -> ConfirmRegistry]`，`workspace_id` 从 `Agent` 实例注入
- `events._sse_emit` → 改为 `dict[connection_id -> push_fn]`，每个 SSE 连接独立注册，`chat.py` 的 worker 携带 `connection_id`
- `BashTool.execute()` → 从 `Agent` 实例上读取 `workspace_root` 作为 `cwd`，不依赖 `os.getcwd()`

这会影响 app state、Agent/Tool 上下文、SSE 生命周期、确认 registry 和测试隔离，不能按“只改 3-4 个文件”估算。只有产品明确需要多 workspace/多用户时再启动。

---

### 6. 通用确认抽象（已完成，2026-08-08）

采用 `corecoder/web/_confirmable.py::request_confirmation()`，没有引入新的 Tool 基类。`edit_file`、`write_file` 和危险 `bash` 共用注册、发事件、串行等待与三态返回流程。

---

## P2 — 安全加固

### 7. bash 黑名单完善

**现状**：`_check_dangerous()` 已覆盖 `rm -rf`、`mkfs`、`dd of=/dev`、块设备覆盖、fork bomb、curl/wget pipe shell 和部分 `chmod 777`。正则仍可能被引号、变量、不同 shell 语法和 PowerShell 命令绕过。

**方案**：

- 增加 Windows/PowerShell 高风险模式及 `chown -R /` 等遗漏项
- 为引号、变量展开、命令链和大小写变体增加参数化测试；不要把正则描述成安全沙箱
- 评估将命令解析改为按平台 tokenizer，避免仅匹配原始字符串
- 保留 CLI 模式的"直接拒绝"行为不变

---

### 8. Markdown 渲染与 XSS 防护

**现状**：agent 回复在 `ChatPanel.vue` 中直接当纯文本 `{{ msg.content }}` 显示，暂无不安全风险。但计划中要把代码块、diff 输出渲染得更可读时，会引入 XSS 面。

**方案**：

- 引入 `marked`（Markdown → HTML）+ `DOMPurify`（清洗 HTML）
- 渲染规则：代码块用 `<pre><code>`（不执行）、链接 `target="_blank" rel="noopener"`、禁止 `<script>` 和内联事件
- 保留原始文本回退（Markdown 解析失败时显示原文）

---

## P3 — 功能扩展

### 9. 文件树搜索/过滤

**现状**：文件树只有展开/折叠，没有搜索。文件多时只靠肉眼找。

**方案**：

- FileTree 顶部加 `<input>` 过滤框
- `watch` 输入 → 模糊匹配文件名 → 高亮匹配结果
- 匹配到但未展开的父目录自动展开，未匹配的节点折叠隐藏

---

### 10. 上下文压缩可视化

**现状**：CoreCoder 的 `context.py` 有三层压缩策略（token 超限时自动裁剪老消息），但前端完全不可见。用户不知道为什么 agent "忘记"了前面的对话。

**方案**：

- `context.py` 压缩时调 `events.emit("context_compressed", {summary, removed_count})`
- 前端 SSE 收到后，在聊天记录中插入一条不可交互的系统提示条："对话过长，已自动压缩：{summary}（移除了 {removed_count} 条旧消息）"

---

### 11. `/resume` 恢复历史会话

**现状**：CLI 的 `-r`（恢复 session）功能依赖 `session.py` 的 `save_session`/`load_session`，这套机制 CoreCoder 已有但没接进 Web。

**方案**：

- 后端新增 `GET /api/sessions` — 列出现有 session 文件列表
- `POST /api/session/{id}/resume` — 加载 session 的 `messages` 灌入当前 `Agent`
- 前端 ChatPanel 顶部加 `<select>` 下拉或侧边栏 session 列表

**注意**：此功能涉及磁盘 I/O，需要确认 session 文件存放位置和 token 安全（session 文件含完整对话历史）。

---

### 12. 文件预览面板

**现状**：点击文件树中的文件只是 `console.log`，没有实际的预览区域。

**方案**：

- App.vue 恢复三列布局（左 FileTree + 中 Chat + 右 Preview）或在 ChatPanel 右侧加可折叠抽屉
- 点击文件时在右侧面板用 `<pre>` + 行号展示文件内容（不超过 500 行 / 50KB，避免大文件撑爆 DOM）
- 复用 `DiffViewer.vue` 的 Monaco 实例做语法高亮（可选）

---

## P4 — 工程质量

### 13. E2E 测试

**现状**：只有后端单元测试（`tests/test_web.py`），前端仅在浏览器手动验证。

**方案**：

- 引入 Playwright
- 测试场景：
  1. 启动 `corecoder web`（用 `ScriptedLLM` 替代真实 API）
  2. 验证 SSE 流式文本渲染
  3. 触发 `edit_file` 确认 → 验证 ConfirmModal 弹出 + diff 预览
  4. 点击 Approve → 验证确认消失 + `tool_end` 到达
  5. 点击 Reject → 验证拒绝消息
  6. 刷新页面 → 验证确认框恢复（`GET /api/session/pending`）

---

### 14. CI 前端构建验证（已完成，2026-08-08）

CI 已在独立 Ubuntu job 中执行 `npm ci`、`npm run type-check` 和 `npm run build`；package 与 publish job 也会先构建 Vue，再构建包含 `static/dist` 的 Python 包。源码环境缺少 dist 时后端会回退到精简前端。

---

### 15. 错误边界

**现状**：Vue 组件抛异常 → 整个 App 白屏。没有任何错误捕获和降级 UI。

**方案**：

- `App.vue` 根组件加 `onErrorCaptured` 钩子
- ChatPanel 外包裹 `<Suspense>` + error fallback 组件
- SSE 连接断开时自动重连（`reader.read()` 抛异常时不崩，显示"连接断开，刷新页面重试"）

---

## 建议执行顺序

```
第一轮（可靠性）:
  1. E2E 测试             (P4-13)
  2. 错误边界与断线提示    (P4-15)
  3. bash 跨平台风险测试   (P2-7)

第二轮（基于测量的体验优化）:
  4. 文件树搜索            (P3-9)
  5. Markdown 渲染与清洗   (P2-8)

第三轮（产品范围扩展）:
  6. 多 workspace 隔离     (P1-5，有明确需求后启动)
  7. 上下文压缩可视化      (P3-10)
  8. /resume 历史会话       (P3-11)
  9. 文件预览面板           (P3-12)
```

P0、并行确认、通用确认函数和前端 CI 已完成，不再重复排期。下一步优先补 E2E、错误边界和 bash 跨平台风险测试；多 workspace 在产品范围明确前不抢先实现。
