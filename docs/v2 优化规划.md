# CoreCoder-Web v2 优化记录：对话工作台

> 版本状态：已完成
> 实施日期：2026-08-08
> 对应提交：`5ad011c`、`f700cf3`

## 1. v2 解决了什么

v2 把 Web 页面从“文件树 + 单个聊天窗口”改成了按工作空间保存的对话工作台。

最终布局是：

```text
┌──────────────────┬────────────────────────────────────┐
│ 当前工作空间       │ 当前对话                            │
│ ＋ 新建对话         │ 消息气泡                            │
│                  │ 执行轨迹                            │
│ 对话历史           │ 最终回复                            │
│                  │ 输入框                              │
└──────────────────┴────────────────────────────────────┘
```

常驻文件树已经移除。工具调用留在对话中，文件修改仍通过确认弹窗查看 Monaco Diff。`/api/tree` 和 `/api/file` 没有删除，后续可以用于文件选择器或 `@文件`。

## 2. 实际交付

### 会话模型与持久化

- 新增 `WebSession` 和 `WebSessionManager`。
- 会话按当前工作空间路径的摘要隔离，存放在 `~/.corecoder/web-sessions/<workspace_id>/`。
- 每个会话有独立消息历史和 Agent 上下文。
- session 文件使用临时文件加原子替换，单个损坏文件不会阻断其他会话加载。
- 服务重启前处于 `running` 或 `waiting_confirmation` 的会话会恢复为 `interrupted`，不会擅自继续执行。
- CLI session 与 Web session 分开保存，没有做隐式迁移。

### 会话接口

v2 新增以下接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/sessions` | 返回当前工作空间的会话列表 |
| `POST` | `/api/sessions` | 新建会话 |
| `GET` | `/api/sessions/{session_id}` | 返回消息和状态 |
| `PATCH` | `/api/sessions/{session_id}` | 修改标题 |
| `DELETE` | `/api/sessions/{session_id}` | 删除会话 |
| `POST` | `/api/sessions/{session_id}/chat` | 发起 SSE 对话 |
| `GET` | `/api/sessions/{session_id}/pending` | 查询待确认操作 |
| `POST` | `/api/sessions/{session_id}/confirm` | 批准或拒绝操作 |

旧的 `/api/chat`、`/api/session/messages` 和 `/api/session/pending` 暂时保留为兼容接口。

### 运行隔离

- SSE 事件携带 `session_id`，前端按事件所属会话更新消息。
- 确认请求只能由对应会话处理。
- 当前版本允许查看其他会话，但同一时间只运行一个 Agent。第二个运行请求返回 `409 Conflict`。
- 页面刷新后可以找回等待确认的操作，并继续跟踪最终结果。
- 长时间没有 token 时，后端发送 SSE 状态帧；前端显示等待阶段和已耗时秒数。

这个限制是有意保留的。事件总线和确认 registry 仍是进程级单例，在完成运行上下文隔离之前，不应该开放多会话并发。

### 前端工作台

- `SessionSidebar` 替换常驻 `FileTree`。
- 支持新建、切换、重命名和删除会话。
- 刷新页面后回到最近打开的有效会话。
- 窄屏下会话栏变成抽屉。
- 用户消息右对齐，Agent 消息左对齐。
- 工具调用按执行顺序显示在最终回复之前，可展开查看参数和结果。
- Monaco Diff 保持点击后加载，不占用固定布局。
- SSE 文本经过字符队列逐字显示；流结束后再用服务端 DTO 校准消息。

### Markdown

提交 `f700cf3` 增加了 Markdown 标题、列表、代码块、引用、表格和链接样式，也将执行轨迹改成透明的可折叠区域。

这部分功能已经可用，但安全工作没有完成：当前组件直接把 `marked` 的结果交给 `v-html`，尚未接入 DOMPurify 或等价清洗。该问题转入 v3 P0，不在这里标成“安全完成”。

## 4. 验证情况

v2 实施时完成了这些验证：

- 后端测试覆盖会话持久化、工作空间隔离、CRUD、单运行锁、损坏 session 容错和确认恢复；
- Ruff 检查通过；
- `vue-tsc --noEmit` 通过；
- Vite production build 通过；
- 浏览器检查覆盖桌面布局、气泡消息、执行轨迹和逐字输出。

Monaco 仍会产生约 2.29 MB 的独立 chunk 警告。它没有进入首页预加载，只有打开 diff 时才下载，因此 v2 没有继续拆分编辑器内核。

## 5. v2 已知限制

### 安全

- Markdown HTML 未清洗，存在 XSS 风险。
- Bash 危险命令检测主要覆盖 POSIX 模式，对 PowerShell、CMD、引号和变量展开处理不足。
- session 文件可能保存代码、命令输出和敏感片段，目前没有权限审计、保留周期或脱敏策略。

### 运行控制

- 用户不能停止正在运行的任务。
- 浏览器断开后，后台 worker 可能继续运行；新页面只能查询状态，不能重连原事件流。
- 事件总线和确认 registry 是全局单例，只能依靠单运行锁保证不串话。

### 性能

- 启动时会读取当前工作空间的全部 Web session，并为每条记录构造 Agent。
- session 每次保存都会重写完整 JSON。
- 流式回复每次字符变化都会重新解析整段 Markdown。
- 对话区在每次字符变化时自动滚到底部，用户向上阅读时也会被拉回。

### 工程质量

- 前端没有组件测试和 E2E。
- Vue 根组件没有错误边界。
- 源码环境的精简 fallback 页面仍沿用旧交互，与正式 Vue 页面不一致。
- 旧单会话 API 尚未移除。

## 6. 结论

v2 的主目标已经完成：CoreCoder-Web 现在是一个能保存多段历史的对话工作台，而不是带文件树的单会话页面。

剩余问题不适合继续塞进 v2。安全、任务取消、断线恢复、长对话性能和自动化测试会由 [`v3 优化规划`](<v3 优化规划.md>) 处理。
