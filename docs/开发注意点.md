通过阅读 CoreCoder 源码，我们其实已经发现：**一个 Coding Agent 从 CLI 变成 Web Agent，不只是加一个 Vue 页面，而是要处理 Agent Runtime、状态管理、工具安全、流式通信、人机协作这些核心问题。**

结合你的 **CoreCoder Web MVP**，我总结一下开发时需要重点注意的点。

---

# CoreCoder Web 开发注意点总结

## 1. 不要重写 Agent，要复用 Runtime

CoreCoder 已经解决了：

```text
用户输入
 ↓
LLM
 ↓
Tool Calling
 ↓
工具执行
 ↓
继续推理
 ↓
最终回答
```

这个核心循环。

所以 Web 化重点不是重新实现 Agent，而是：

```text
CLI
 |
 | 替换
 ↓
Web Interface

Vue
 |
FastAPI
 |
CoreCoder Runtime
```

---

# 2. 明确两个循环：Web交互循环 ≠ Agent执行循环

CoreCoder：

## 外层循环（CLI/Web）

负责：

* 用户输入
* 展示消息
* 接收确认

现在：

```text
while True:
    用户输入
    agent.chat()
    展示结果
```

未来：

```text
Vue输入
 ↓
POST /chat
 ↓
SSE返回事件
```

---

## 内层循环（Agent）

负责：

* 调 LLM
* 判断 tool_call
* 执行工具
* 继续推理

不要把这部分逻辑塞进 FastAPI。

正确：

```
FastAPI
    |
    |
 Agent Runtime
    |
    |
 Tool
```

---

# 3. SSE 不只是传文本，要设计事件模型

CoreCoder CLI 使用：

```python
on_token()
on_tool()
```

作为事件出口。

Web 版应该扩展成：

```json
{
"type":"token",
"content":"正在分析..."
}
```

例如：

---

## AI文本

```json
{
"type":"message",
"data":"我发现项目包含..."
}
```

---

## 工具调用

```json
{
"type":"tool_call",
"name":"read_file",
"args":{
    "file_path":"agent.py"
}
}
```

---

## 工具结果

```json
{
"type":"tool_result",
"result":"..."
}
```

---

## 等待人工确认

你的创新点：

```json
{
"type":"approval_required",
"tool":"edit_file",
"diff":"..."
}
```

---

不要只返回最终结果：

```json
{
"answer":"完成"
}
```

否则失去了 Agent 的过程展示。

---

# 4. Tool Calling 要保持清晰边界

CoreCoder 的设计：

```text
LLM
 |
产生工具调用
 |
程序执行工具
```

不要让：

```text
LLM
 |
直接修改文件
```

---

工具负责：

* read_file
* write_file
* edit_file
* bash

LLM 负责：

* 判断调用什么工具
* 生成参数

---

# 5. Human-in-the-loop 应该插在 Tool 执行层

现在 CoreCoder：

```
LLM
 |
edit_file
 |
执行修改
```

你的目标：

```
LLM
 |
edit_file
 |
生成修改方案/diff
 |
暂停
 |
用户确认
 |
继续执行
```

不要放：

❌ 前端判断

❌ Prompt里面要求模型确认

应该：

```python
_execute_tool()

        ↓

check approval

        ↓

execute
```

---

# 6. Agent 状态必须可恢复

CoreCoder 的 Ctrl+C 处理给你的启发：

Agent 随时可能中断：

* 用户关闭网页
* 网络断开
* 用户拒绝修改
* 服务异常

不能留下：

```
assistant:
我要调用 edit_file

(tool结果不存在)
```

这种非法状态。

你的状态应该类似：

```python
TaskState:

{
 session_id,
 workspace,
 messages,
 status,
 pending_tool,
 pending_diff
}
```

例如：

状态：

```
RUNNING

↓

WAIT_CONFIRM

↓

APPROVED

↓

COMPLETED
```

---

# 7. 工具必须考虑并发安全

CoreCoder 的 bash cwd 问题：

错误：

```python
cwd = global_variable
```

多个 Agent：

```
用户A
 |
bash


用户B
 |
bash
```

会互相污染。

你的 Web 版以后可能：

```
用户A workspace=A

用户B workspace=B
```

所以：

不要：

```python
current_workspace = xxx
pending_confirm = xxx
```

放全局。

应该：

```python
Session
    |
    workspace
    |
    messages
    |
    pending_confirm
```

隔离。

---

# 8. Workspace 设计要安全

你的启动方式：

```bash
cd 项目目录

corecoder web
```

这个设计很好。

因为：

```python
workspace=os.getcwd()
```

天然可信。

但是：

所有文件操作必须限制：

```
workspace
    |
    |
    ↓
允许访问
```

不能：

```
workspace
    |
    ↓
../../用户密码文件
```

---

所有：

* read_file
* write_file
* edit_file

都应该：

```python
real_path = Path(path).resolve()

检查:

real_path 是否属于 workspace
```

---

# 9. LLM调用层不要污染Agent

CoreCoder：

```
agent.py

只负责:
循环
工具
状态


llm.py

负责:
API调用
stream
retry
provider兼容
```

你的项目也应该：

```
FastAPI
 |
Agent
 |
LLM Client
```

不要：

```python
FastAPI接口里面：

调用DeepSeek
处理stream
处理retry
```

---

# 10. 保留错误分类思想

CoreCoder：

区分：

## 参数错误

例如：

```text
tool参数缺少file_path
```

告诉模型：

> 参数重新生成

---

## 工具执行错误

例如：

```text
文件不存在
```

告诉模型：

> 工具执行失败

---

不要全部：

```python
except Exception:
    返回错误
```

否则 Agent 无法自我修正。

---

# 11. Session设计不要简单保存文件

CoreCoder：

session保存：

```
messages
model
timestamp
```

并且防：

```
../../xxx
```

你的 Web：

建议：

数据库保存：

```
sessions
    |
    ├── id
    ├── workspace
    ├── status
    └── messages
```

不要直接：

```
session_id.json
```

---

# 12. 第一版 MVP 建议保留什么

根据源码学习，优先级：

## 必做 ⭐⭐⭐⭐⭐

### Agent Runtime

复用 CoreCoder：

* tool calling
* agent loop

### Web通信

* FastAPI
* SSE

### Workspace绑定

```
corecoder web
```

获取当前目录。

### Human-in-the-loop

重点：

* edit_file确认
* bash确认

---

## 可以后置 ⭐⭐⭐

### Session恢复

先简单：

内存保存。

后面：

数据库。

### 多用户

先单用户。

---

## 暂时不要做 ⭐⭐

* 多 Agent复杂编排
* MCP
* RAG
* 自动部署
* 权限系统

## 最重要的三个经验

如果只记三个：

### 1.

**Agent核心不要动，Web只是替换交互层。**

---

### 2.

**Human-in-the-loop不是前端功能，而是Agent执行状态管理。**

---

### 3.

**所有带状态的东西都必须考虑隔离和恢复。**
