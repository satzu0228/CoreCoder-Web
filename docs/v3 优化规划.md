# CoreCoder-Web v3 优化规划：可靠的长任务执行

> 规划日期：2026-08-08
> 当前基线：`f700cf3`
> 前置版本：[v2 优化记录](<v2 优化规划.md>)

## 1. v3 目标

v2 解决了“对话怎么组织”。v3 解决“任务怎么安全、稳定地跑完”。

这一版集中处理四类问题：

- 关闭已经确认的安全缺口；
- 让长任务可以停止、恢复和解释当前状态；
- 控制会话与流式渲染的资源消耗；
- 建立前端自动化测试，减少靠截图和手工回归发现问题。

v3 仍按本地单用户工具设计，不引入账号系统、远程部署和团队权限。多会话并行也不是默认目标，必须等运行上下文真正隔离后再决定。

## 2. 当前还需要优化的地方

| 优先级 | 问题 | 当前证据 | 影响 |
| --- | --- | --- | --- |
| P0 | Markdown XSS | `MarkdownContent.vue` 使用 `v-html`，只有 `marked`，没有 HTML 清洗 | 模型输出可能执行脚本、危险链接或事件属性 |
| P0 | 任务无法取消 | 没有 cancel API、取消信号和停止按钮 | 长任务、卡住的模型或命令只能等待超时或重启服务 |
| P0 | 断线后不能恢复事件流 | POST SSE 只绑定原连接，worker 继续运行但事件不会重放 | 刷新或网络抖动后看不到中间过程 |
| P0 | 流式 Markdown 重复解析 | 每个字符都会重新执行 `marked.parse()` | 长回复越到后面越卡，代码块和表格更明显 |
| P1 | 自动滚动不可控 | 消息内容每变化一次就强制滚到底部 | 用户阅读旧消息时被拉回底部 |
| P1 | 运行状态仍是全局单例 | `events._sse_emit`、`ConfirmRegistry.registry` 是模块级对象 | 阻碍并发，也让会话隔离依赖单运行锁 |
| P1 | Agent 共享可变依赖 | 多个 WebSession 共用 LLM 和 tool 实例 | token 统计、`AgentTool._parent_agent` 和未来并发存在耦合 |
| P1 | session 读写会随历史增长 | 启动加载全部 JSON；保存重写全部消息 | 大量会话或大工具输出会拖慢启动和确认流程 |
| P1 | session 数据缺少治理 | 没有大小上限、权限检查、保留周期和导出策略 | 磁盘持续增长，敏感内容长期留存 |
| P1 | Bash 检测偏 POSIX | 规则缺少 PowerShell/CMD 模式，也容易被变量和引号绕过 | Windows 环境的危险命令可能不触发确认 |
| P1 | 前端缺少测试与错误边界 | CI 只有类型检查和构建，没有 Vitest/Playwright | 交互回归常在实际使用时才暴露 |
| P2 | 兼容层和 fallback 页面陈旧 | 旧 session API 与精简 HTML 页面仍在 | 维护两套行为，容易出现文档和实现不一致 |
| P2 | 对话管理能力有限 | 没有搜索、归档、批量清理 | 会话积累后难以整理 |
| P2 | 文件引用入口缺失 | 文件 API 保留，但聊天框无法选择或引用文件 | 用户只能手写路径，长路径体验差 |
| P2 | 上下文状态不可见 | 压缩、token 使用量和模型成本未展示 | 用户不知道历史何时被压缩，也无法判断上下文压力 |

## 3. 设计约束

### 只展示可观察过程

执行轨迹显示工具调用、确认、结果、等待和错误。这些都是系统真实发生的事件。v3 不展示或伪造模型的隐藏思维链。

### 运行任务有唯一标识

`session_id` 表示对话，`run_id` 表示一次执行。两者不能继续混用。

```text
Session A
  ├─ Run 1  completed
  ├─ Run 2  cancelled
  └─ Run 3  running
```

确认请求、事件序号和取消信号都归属于 `run_id`。这样刷新、重试和未来并发才有明确边界。

### 先保证单任务可靠，再讨论并发

v3 前半段继续保留单运行锁。只有事件总线、确认 registry、工具上下文和 LLM 实例都完成隔离，才评估多会话后台运行。

## 4. M0：安全补洞（P0）

### Markdown 清洗

- 引入 DOMPurify 或同等能力的白名单清洗器；
- 禁止 `script`、`style`、iframe、内联事件和危险 URL scheme；
- 链接只允许 `http`、`https`、`mailto` 和站内锚点；
- 对 title、href 和自定义 renderer 输出做属性转义；
- 添加 XSS 用例，覆盖大小写混淆、SVG、`javascript:`、data URL 和破损标签。

流式阶段优先显示转义后的纯文本或低频更新的安全 Markdown，结束后再做一次完整渲染。不要在每个字符变化时把未经清洗的 HTML 交给 DOM。

### Bash 风险识别

- 补 PowerShell：`Remove-Item -Recurse -Force`、格式化卷、磁盘写入、下载后执行等模式；
- 补 CMD：`del /s /q`、`rmdir /s /q`、`format` 和注册表破坏命令；
- POSIX 规则改为大小写、引号、短参数组合和命令链参数化测试；
- 明确规则的边界：它是风险提示，不是完整 shell 沙箱；
- CLI 继续直接拒绝，Web 继续要求人工确认。

### 验收

- OWASP 常见 XSS payload 不能执行；
- Markdown 正常的代码块、表格和链接不受影响；
- 三个平台的高风险命令测试进入 CI；
- 安全失败时默认拒绝，不降级为直接执行。

## 5. M1：任务取消与事件恢复（P0）

### RunContext

新增运行上下文：

```text
RunContext
  run_id
  session_id
  status
  started_at
  cancel_event
  confirm_registry
  event_sequence
  event_buffer
```

状态机统一为：

```text
idle → running → waiting_confirmation → running → completed
          ├→ cancelling → cancelled
          ├→ interrupted
          └→ error
```

所有状态变化由一个方法完成，并校验非法跳转。

### 取消流程

- 新增 `POST /api/runs/{run_id}/cancel`；
- 聊天输入区在运行时显示“停止”，不只是禁用发送；
- Agent 循环每轮检查取消信号；
- 确认等待收到取消后立即释放；
- Bash 子进程使用进程组，取消时终止整个子进程树；
- 无法中断的 LLM 请求标记为 `cancelling`，请求返回后不再执行后续工具。

### 事件恢复

每个事件带单调递增的 `sequence`。服务端保留当前 run 的有限事件缓冲区。

- 新连接携带 `after=<last_sequence>`；
- 服务端重放缺失事件，再继续发送实时事件；
- 缓冲区过期时返回完整会话 DTO 和明确的 `resync_required`；
- 前端保存最后处理的 sequence，重复事件不会再次追加工具卡片。

### 验收

- 点击停止后 2 秒内进入 `cancelled` 或清楚显示仍在取消；
- 取消等待确认的任务不会继续写文件或执行命令；
- 刷新页面后不丢失工具开始、结束和最终回复；
- 同一事件重放两次不会产生重复消息。

## 6. M2：流式体验与前端稳定性（P1）

### 渲染性能

- 流式阶段以 30–50ms 节流更新 DOM；
- 不在每个字符上重新解析整段 Markdown；
- 回复完成后再执行完整 Markdown 清洗和渲染；
- 长代码块按需高亮，不引入首页级编辑器依赖；
- 对超长工具结果只渲染摘要，展开时再挂载正文。

字符逐个播放可以保留，但它是展示队列，不应阻塞服务端状态完成，也不能让 5000 字回复多等一分钟。队列积压超过阈值时应平滑加速，并保持视觉连续。

### 智能滚动

- 用户位于底部附近时自动跟随新内容；
- 用户向上滚动后停止自动跟随；
- 显示“回到最新消息”按钮；
- 切换会话时恢复各自滚动位置。

### 错误处理

- 根组件增加错误边界和可恢复页面；
- SSE、确认、会话保存和 Markdown 渲染使用统一错误提示；
- 失败消息提供重试入口，但不自动重复可能有副作用的工具调用；
- 删除 `console.error` 作为唯一反馈的路径。

### 验收

- 5000 字 Markdown 流式输出期间输入和滚动保持可用；
- 用户向上阅读时不会被新 token 拉回底部；
- 单个组件异常不会让整个页面白屏；
- 网络错误能说明当前任务是否仍在后台运行。

## 7. M3：会话存储与运行隔离（P1）

### 会话索引

- 单独保存轻量 metadata 索引，列表接口不读取完整消息；
- `GET /api/sessions` 增加游标分页和搜索参数；
- Agent 在打开会话或运行任务时再构造；
- session schema 增加版本和迁移函数。

### 写入策略

- 消息完成和状态变化分开保存，避免每个短状态都重写大 JSON；
- 保存移出 SSE 推送路径，写盘失败通过状态事件反馈；
- 对工具结果、单会话文件和工作空间总量设置可配置上限；
- 增加归档、导出和清理入口；
- Unix 下显式使用仅当前用户可读写的目录和文件权限。

### 依赖隔离

- 使用 factory 为每个 Agent 创建独立 tool 实例；
- 明确 LLM 客户端是否共享连接池，token 统计按 session/run 记录；
- 把 `AgentTool._parent_agent` 从共享可变字段改为运行上下文参数；
- 将事件 emitter 和确认 registry 收进 `RunContext`，移除模块级单例。

### 验收

- 1000 个会话的首屏列表不加载完整消息；
- 10 MB 历史保存不会阻塞 SSE heartbeat；
- 进程崩溃不会留下半写入的正式 session；
- 会话之间没有共享的可变 tool 状态。

## 8. M4：自动化测试和兼容层收口（P1）

### 前端测试

- 引入 Vitest 和 Vue Test Utils；
- 覆盖 session store、SSE parser、字符队列、Markdown 清洗和智能滚动；
- 用 fake timer 验证等待状态与逐字输出，避免再次出现“内部内容变化但 Vue 不重绘”。

### E2E

Playwright 使用 `ScriptedLLM`，不访问真实模型：

1. 新建两个会话并切换；
2. 流式文本逐步增长；
3. 多个工具步骤按事件顺序出现；
4. edit/write diff 批准和拒绝；
5. 刷新后重放事件；
6. 取消运行中的任务；
7. 重启服务后恢复历史。

### 收口

- 把 Vitest 和 Playwright 加入 CI；
- 为 session/run API 固定响应 schema；
- 前端全部切换完成后删除旧单会话接口；
- 精简 fallback 页面改为明确的“前端尚未构建”提示，或者随源码开发流程自动构建，不再维护第二套聊天实现。

### 验收

- 核心对话流程不依赖人工截图回归；
- CI 能捕获 SSE 顺序、确认恢复和 XSS 回归；
- README、API 文档和运行行为只有一套现行描述。

## 9. M5：使用效率（P2）

前四个阶段稳定后再选择：

- 对话搜索、归档和批量清理；
- `@文件`、最近文件和路径补全；
- 上下文压缩记录、token 使用量和成本提示；
- 代码块复制、工具结果复制和会话导出；
- 自动标题或手动固定重要会话；
- 多会话后台运行。

多会话并发必须单独验收 CPU、内存、确认归属和工具 cwd，不能只移除单运行锁。

## 10. 建议实施顺序

```text
1. Markdown 清洗与 XSS 测试
2. Bash 跨平台危险命令测试
3. RunContext、取消 API 和停止按钮
4. 事件序号、缓冲与断线重放
5. 流式 Markdown 节流和智能滚动
6. 前端错误边界
7. session 索引、分页和写入优化
8. emitter / registry / tool 实例隔离
9. Vitest、Playwright 和 CI
10. 删除兼容接口与旧 fallback 交互
11. 根据使用反馈选择 P2 功能
```

安全补洞排在第一位。任务取消和断线恢复紧随其后，因为它们直接决定长任务是否可控。存储扩展和并发隔离不能抢在运行模型稳定之前做。

## 11. v3 完成定义

v3 完成时应满足：

- Markdown 输出经过可靠清洗，已知 XSS payload 有自动化测试；
- 用户可以停止任务，刷新后可以继续接收或重放事件；
- 长回复不会因重复 Markdown 解析和强制滚动明显卡顿；
- session 列表按索引和分页加载，写盘不会阻塞事件流；
- 事件、确认和工具上下文不再依赖模块级单例；
- 前端组件测试和核心 E2E 进入 CI；
- 旧单会话接口与旧 fallback 聊天实现退出主路径；
- 文档明确区分已完成能力、已知限制和可选功能。
